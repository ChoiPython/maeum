# 마음정원: 대학생을 위한 감정 반응형 메타버스 힐링 공간

교과목: 메타버스이론및실습 / 수행팀: 8팀

수행기간: 2026.09.19~2026.12.07

## 수정안 작성 기준

이 문서는 「메타버스이론및실습_8팀_계획서.pdf」의 본문, 일정표, 역할표, 참고문헌과 사용자가 전달한 교수 피드백을 반영한 개발계획 수정안이다. 기존의 세 가지 핵심 공간과 5~10분 체험은 유지하되, 주 개발 환경을 Three.js 기반 웹 3D로 제안하고 3인 팀의 기능별 책임과 산출물을 명시하였다. 역할 배정은 기존 역할표를 확장한 제안이며, 실제 개인별 숙련도에 따른 최종 합의가 필요하다. 별도로 언급된 ‘선택된 소스’의 목록이나 내용은 이 대화에서 확인되지 않아 검토한 것으로 간주하지 않았다.

교수 피드백의 핵심은 특정 도구 이름을 추가하는 데 그치지 않고, 어느 도구로 어떤 장면과 기능을 구현할지, 누가 그 기능을 완성할지 설명하는 것이다. Roblox가 기술적으로 안개와 꽃 연출을 구현할 수 없다는 뜻으로 해석하지 않고, 마음정원의 표현 목적에 맞춰 환경 연출과 이용 흐름을 직접 구성하는 방향으로 개발 방식을 재설계한다.

# I. 서론

## 1. 프로젝트의 배경 및 필요성

대학생은 학업, 진로, 취업, 경제적 부담과 대인관계 등 여러 과제를 동시에 경험한다. 이러한 부담은 시험 기간에 한정되지 않고 대학생활 전반에 나타나므로 학생이 자신의 감정을 돌아보고 잠시 쉬어갈 수 있는 일상적인 휴식 콘텐츠가 필요하다.

한국보건사회연구원의 「청년 건강 실태와 정책과제」에서 제시한 2024년 청년 삶 실태조사 자료에 따르면 전체 청년의 최근 1년 이내 소진 경험률은 32.2%, 대학 재학·휴학 집단은 29.7%였다. 대학 재학·휴학 집단의 우울증상 경험률도 2022년 4.7%에서 2024년 6.4%로 증가하였다[1]. 우울증상 경험률은 PHQ-9 점수 10점 이상인 비율이며 의사의 우울증 진단율과 구분해야 한다.

가상 자연환경을 다룬 선행연구는 자연의 시각·청각 요소를 디지털 공간에 적용하는 가능성을 제시한다[2][3]. 본 프로젝트는 이 가능성을 참고하되, 자체 콘텐츠의 효과를 이미 입증된 것으로 표현하지 않고 대학생 사용자 평가를 통해 사용성과 체험 직후의 반응을 확인한다.

기존 계획은 공간의 의미와 사용자 흐름이 제시되어 있으나 제작 프로그램과 기능별 책임자가 충분히 구체적이지 않았다. 이에 오픈소스 3D 라이브러리와 공개 에셋을 활용하여 자연공간, 안개, 빛, 꽃과 오브젝트의 변화를 직접 설계하고, 개발 담당자와 완료 기준을 명확히 정의한다. 소규모 프로젝트에 맞춰 하나의 정원과 세 개의 활동 구역을 구현하며, 대학생의 정서적 휴식이라는 목적에 필요한 기능부터 완성한다.

## 2. 프로젝트의 목표

최종목표는 PC 웹브라우저에서 이용할 수 있는 감정 반응형 3D 힐링 공간 ‘마음정원’을 제작하는 것이다. 이용자는 현재 감정을 직접 선택하고 적합한 활동을 추천받으며, 가상공간을 이동하고 오브젝트와 상호작용한 뒤 체험 전후의 상태를 돌아본다. 연결의 광장에서는 소수의 이용자가 같은 공간에 접속하여 선택형 응원 문구를 전달할 수 있도록 한다.

| 항목 | 목표 및 완료 기준 |
|---|---|
| 공간 규모 | 하나의 정원에 호흡의 숲·비움의 호수·연결의 광장 3구역 구성 |
| 이용 시간 | 기본 안내 동선을 기준으로 5~10분 체험 |
| 핵심 기능 | 감정 선택·활동 추천·호흡 안내·고민 내려놓기·응원 전달·체크아웃 6개 기능 |
| 개인화 | 선택한 감정에 따라 추천 구역과 안내 문구 변경; 호흡 진행에 따라 개인 화면의 안개와 꽃 변화 |
| 공동 체험 | 동일한 서버에 3~5명이 접속해 단순 아바타 이동과 선택형 응원 전달 확인 |
| 지원 환경 | PC Chrome·Edge 우선; 모바일 조작과 VR은 후속 확장 |
| 사용자 평가 | 대학생 15~20명 대상; 주요 동선 완료율 80% 이상, 편의성·만족도 평균 4.0/5.0 목표 |
| 성능 | 팀 테스트 PC에서 1366×768 화면 기준 주요 구역 평균 30FPS 이상 목표; 장치 사양과 측정 조건 기록 |

이 수치는 개발 및 평가의 목표이며 현재 달성한 결과를 뜻하지 않는다. 실제 구현과 테스트 후 결과보고서에 달성 여부를 기재한다.

# II. 프로젝트 수행내용

## 1. 프로젝트의 내용

### 1) 제작 프로그램과 개발 환경

주 개발 방식은 **Three.js + TypeScript + Vite**를 이용한 웹 3D 구현으로 정한다. Three.js로 공간과 시각적 변화를 표현하고, Blender에서 모델의 형태·색상·크기를 정리하며, 웹 UI로 감정 선택과 안내를 제공한다. 소규모 공동 접속은 Node.js와 Socket.IO로 구현한다. Three.js는 완성된 메타버스 플랫폼이 아니라 웹 3D 라이브러리이므로 이동, 활동 진행, 공동 접속과 응원 전달은 팀이 직접 개발한다[4][6].

| 구분 | 도구·기술 | 프로젝트에서 사용하는 목적 |
|---|---|---|
| 3D 렌더링 | Three.js / WebGLRenderer | 정원, 카메라, 조명, 안개와 오브젝트 표현 |
| 기능 개발 | TypeScript | 감정 추천 규칙, 활동 타이머, 상호작용 상태 관리 |
| 화면 구성 | HTML·CSS | 감정 버튼, 활동 안내, 진행률, 응원 선택, 결과 화면 |
| 개발·빌드 | Vite | 개발 서버 실행과 배포용 웹 파일 생성 |
| 모델 편집 | Blender | 공개 에셋 색상·크기 조정, 단순 모델 제작, GLB 형식으로 정리 |
| 모델 로딩 | Three.js GLTFLoader | GLB 모델을 웹 3D 장면에 배치 |
| 공동 접속 | Node.js + Socket.IO | 임시 접속자 위치와 검수된 응원 문구의 식별자 전달 |
| 음향 | 브라우저 오디오 / Three.js Audio | 자연음 반복 재생과 음량 조절 |
| 에셋 | Kenney·Poly Haven의 CC0 자료 | 저작권 이용조건을 확인한 자연 모델·재질·배경 활용 |
| 편집·협업 | VS Code, Git·GitHub | 코드 작성, 작업별 버전 기록, 기능 통합 |

Three.js, Vite, Socket.IO의 공식 문서와 예제를 학습자료로 활용한다[4][5][6]. 공개 에셋은 프로그램 소스코드와 구분하며, Kenney와 Poly Haven의 CC0 이용조건을 확인한 뒤 사용한다[7][8]. 선택한 각 파일의 이름·제작자·URL·라이선스·수정 내용을 에셋 목록에 기록한다. 나무·꽃·바위는 색상과 형태가 통일된 저폴리 모델을 우선 사용하고, 고해상도 재질과 사실적인 물 시뮬레이션은 최소화한다.

프런트엔드는 3D 화면과 개인 활동을 처리하고, 서버는 소수 접속자의 위치 및 응원 메시지만 전달한다. 감정 선택과 고민 유형은 이용자의 브라우저 메모리에서만 처리하며 다른 이용자에게 전송하지 않는다. 서버에는 회원가입과 데이터베이스를 두지 않고 접속 중인 임시 데이터만 유지한다. 실제 여러 이용자에게 응원을 전달하기 위해서는 실행 중인 Node.js 서버가 필요하다. 초기 테스트는 동일한 실습 네트워크에서 진행하고, 외부 접속이 필요한 경우 웹 파일과 실시간 서버를 제공할 실행 환경을 별도로 확보한다. 공개 배포는 개발 결과가 준비된 후 진행한다.

### 2) 공간 구성과 기능별 구현 방법

시작의 정원은 독립된 대형 공간 대신 입구와 안내판으로 간소화한다. 사용자는 키보드로 단순 아바타를 이동하고 마우스로 오브젝트를 선택한다. 세 개의 활동 구역은 하나의 연결된 맵에 배치하여 공간 로딩과 파일 관리의 부담을 줄인다.

| 기능 | 이용자 행동과 화면 변화 | 구현 방법 | 완료 기준 |
|---|---|---|---|
| 감정 체크인·추천 | 현재 감정 선택 후 추천 구역과 안내 문구 표시 | HTML 버튼과 TypeScript 규칙표 | 모든 선택지가 정해진 추천 구역으로 연결되고 변경 가능 |
| 호흡의 숲 | 시작 버튼을 누르면 빛이 커졌다 작아짐; 60초 안내 동안 안개가 옅어지고 완료 후 꽃이 나타남 | 활동 타이머, 오브젝트 크기 변화, FogExp2, 꽃 모델 표시 | 중단·다시 시작·완료가 구분되고 반복 실행 오류 없음 |
| 비움의 호수 | 고민 유형을 선택하고 나뭇잎을 흘려보내면 물 위로 이동한 뒤 사라짐 | 버튼 입력, Raycaster, 위치·투명도 애니메이션 | 선택한 오브젝트가 정해진 경로로 이동하며 중복 입력 방지 |
| 연결의 광장 | 6개 검수된 응원 중 하나를 선택해 같은 공간의 다른 접속자에게 전달 | 문구 ID 검증, Socket.IO 이벤트, 카드 UI | 두 개 이상의 독립된 접속 화면에서 송수신 확인 |
| 감정 체크아웃 | 현재 긴장감·편안함에 다시 응답하고 본인의 전후 값을 확인 | 브라우저 메모리 상태와 결과 UI | 전후 응답이 뒤바뀌지 않고 새 체험 시작 시 초기화 |
| 마음 씨앗 | 체험 완료 시 기념 아이콘 표시 | UI 아이콘 표시 | 해당 체험 내에서만 표시; 수집·거래 기능 없음 |

호흡 활동은 실제 호흡을 감지하지 않는다. 따라서 ‘호흡 성공’ 대신 ‘60초 호흡 안내 활동 완료’라고 표시한다. 화면을 벗어나거나 중단하면 진행을 멈추며, 돌아와 재개하거나 다시 시작할 수 있도록 한다. 활동 완료 시 제공되는 안개와 꽃의 변화는 타이머 진행에 따른 시각적 피드백이다.

감정별 환경 변화는 개인의 화면에만 적용한다. 한 사용자의 호흡 활동으로 다른 사용자의 안개가 함께 바뀌지 않도록 한다. 공동으로 공유하는 정보는 단순 아바타 위치와 검수된 응원 문구로 제한한다. 이동은 제한된 평면 동선을 사용하고 점프, 정교한 물리연산, 캐릭터 충돌과 복잡한 움직임 동기화는 구현 범위에서 제외한다.

서버는 허용된 응원 문구 ID만 처리하고 전송 간격을 제한한다. 접속자가 혼자인 경우에는 시스템이 제공하는 응원 문구라고 표시하며, 이를 실제 다른 이용자가 보낸 메시지로 표현하지 않는다. 연결이 끊기면 공동 전달 기능의 상태를 안내하되 호흡과 고민 활동은 계속 이용할 수 있게 한다.

### 3) 프로젝트 설계의 독창성

마음정원은 대학생의 감정 선택을 활동 추천으로 연결하고, 행동의 결과를 공간 변화로 보여주는 짧은 체험 과정에 차별성이 있다. 사용자는 자연을 감상하는 것에 더해 빛의 움직임에 맞춰 호흡하고, 고민을 상징하는 오브젝트를 내려놓으며, 검수된 응원을 전달한다. 오픈소스 라이브러리와 공개 에셋을 목적에 맞게 조합하여 공간 분위기와 활동 진행을 직접 설계한다.

특히 개인적인 감정 체험과 공동 활동의 범위를 구분한다. 감정·고민 정보와 안개 변화는 개인에게만 표시하고, 연결의 광장에서는 접속자의 존재와 응원만 공유한다. 이는 정서적인 사생활을 유지하면서 제한된 사회적 연결을 경험하도록 하는 설계이다. 오픈소스 사용 자체를 독창성으로 주장하지 않고, 감정 선택·상호작용·안전한 연결을 구성한 방식에 독창성을 둔다.

### 4) 사용자 평가와 범위 관리

먼저 팀 내부에서 입장, 감정 선택, 이동, 세 가지 활동, 체크아웃의 전체 흐름을 점검한다. 대학생 15~20명을 대상으로 사전·사후 긴장감과 편안함을 동일한 5점 문항으로 묻고, 편의성·몰입감·만족도·재이용 의향을 조사한다. 주요 활동 완료 여부, 오류와 소요시간도 기록한다. 설문 참여는 자발적으로 진행하고 게임 접속 식별자와 설문 응답을 연결하지 않는다.

PHQ-9은 최근 2주간의 상태를 묻는 도구이므로 5~10분 체험 전후 평가에는 사용하지 않는다. 평균 변화와 서술형 의견은 사용성 및 체험 직후 반응으로 해석하며, 대조군이 없는 소규모 조사에서 치료 효과나 인과관계를 주장하지 않는다.

필수 구현은 작은 정원, 세 활동, 감정 UI, 3~5명 공동 접속과 선택형 응원으로 한정한다. 얼굴·음성 감정 분석, 자유 입력 고민, 자유 채팅, 계정, 데이터베이스, 사실적인 물리·물 시뮬레이션, 모바일 전용 조작과 VR은 후속 과제로 구분한다. 단일 사용자 기능부터 제작하고 연결의 광장을 붙이되, 최종 메타버스 시연에서는 실제 두 명 이상이 접속하는 장면을 포함한다.

### 2) 프로젝트 추진 체계와 역할 정의

기존 PDF의 세 팀원과 기본 담당 영역을 유지하면서 개발 책임을 보완한 배정안이다. 팀장은 기획뿐 아니라 공통 구조와 실시간 전달 기능을 맡고, 공간 담당자는 모델과 공간 내 오브젝트 활동을, UI 담당자는 감정·호흡 진행·결과 화면을 맡는다.

| 성명 / 학번 | 역할 | 주 책임 업무 | 제출 산출물 | 완료 확인 방법 |
|---|---|---|---|---|
| 최주영 / 학번 비공개 | 팀장·시스템 통합·공동 접속 개발 | 공통 프로젝트와 이동 구조, Node.js·Socket.IO 서버, 아바타 위치·응원 전달, 전체 통합·일정 관리 | 실행 프로젝트, 서버 코드, 이벤트 정의서, 통합 테스트표, 최종 보고서 | 한 실행 절차로 접속 가능; 두 화면 이상에서 접속·이동·응원 전달 확인 |
| 장재혁 / 학번 비공개 | 3D 공간·에셋·환경 연출 개발 | Blender 모델 정리, 3구역 배치, 조명·안개·꽃 변화, 고민 나뭇잎 이동·소멸, 환경음 배치 | GLB 모델, 공간 코드, 환경·호수 효과 코드, 에셋 출처표 | 3구역 이동 가능; 호흡 진행 이벤트에 안개·꽃 반응; 호수 활동 작동 |
| 심가현 / 학번 비공개 | UI·체험 흐름·사용자 평가 | 감정 체크인·추천, 60초 호흡 안내 타이머, 응원 선택 UI, 체크아웃·결과 화면, 설문·평가 분석 | UI 코드, 추천 규칙표, 활동 상태 정의, 검수 문구 6개, 설문·분석 결과 | 모든 감정 선택 작동; 활동 중단·재개·완료 구분; 전후 결과 정확히 표시 |

팀원 간 연결 지점도 사전에 합의한다. 심가현은 호흡 활동의 진행률과 완료 상태를 전달하고, 장재혁은 그 값을 받아 안개와 꽃 연출을 갱신한다. 장재혁은 호수 오브젝트와 활동 함수를 제공하고, 심가현은 선택 UI를 연결한다. 심가현은 선택한 응원 문구의 ID를 전달하고, 최주영은 서버에서 허용 목록을 확인해 다른 접속자에게 전송한다.

각 기능은 주 담당자가 구현·수정·사용 설명을 책임지고 다른 한 명이 작동을 검토한다. 최주영의 서버·이동은 심가현이, 장재혁의 공간·연출은 최주영이, 심가현의 UI·평가는 장재혁이 확인한다. 전원 공동작업이라는 표현만으로 책임을 묶지 않고, 오류 목록마다 담당자와 수정 상태를 기록한다. 사용자 모집과 체험 진행, 최종 발표는 전원이 참여하되 설문 운영과 결과 집계의 책임자는 심가현으로 정한다.

### 3) 협업 및 개발 규칙

코드는 Git으로 관리하고 기능별 작업을 완료하면 다른 팀원 검토 후 통합한다. Three.js 및 관련 패키지 버전은 최초 검증 시 확정하고 잠금 파일로 공유한다. 팀원마다 같은 Node.js 버전과 실행 안내를 사용한다. 오픈소스 예제는 라이선스를 확인하고 수정 내용을 기록한다.

공간 파일은 숲·호수·광장별로 구분하고 감정 규칙과 응원 문구는 공통 설정 파일로 관리한다. 모델 파일의 이름, 크기, 원점, 좌표 규칙을 통일하며 나무·꽃·호수 오브젝트는 반복 배치가 가능한 형태로 정리한다. 큰 에셋은 용량을 줄여 공유하고 불필요한 원본 파일을 실행 결과물에 포함하지 않는다.

# III. 결론

## 1. 프로젝트 결과의 활용방안

마음정원은 대학생이 PC 브라우저에서 짧게 이용할 수 있는 체험 콘텐츠로 활용한다. 수업 발표, 대학 행사와 비교과 프로그램에서 시연하고, 이용자의 반응을 바탕으로 공간과 안내를 개선할 수 있다. 교내 학생상담센터와의 연계는 향후 협의를 통해 공식 지원정보를 제공하는 방향으로 추진하며 현재 연계가 확정된 것으로 표현하지 않는다.

결과물에는 웹 실행 파일과 서버 코드, Blender 모델, 에셋 출처표, 사용자 평가 결과와 실행 설명서를 포함한다. 다른 대상에 맞춰 안내 문구와 모델을 바꿀 수 있도록 기능과 콘텐츠를 구분하여 구성한다.

# IV. 기타

감정과 고민은 사용자 브라우저 메모리에서만 처리하고 새로고침·종료 시 유지하지 않는다. 공동 접속 서버에는 임시 아바타 위치와 검수된 문구 ID만 전송하며, 메시지는 짧은 시간 동안 표시한 뒤 제거한다. 본 콘텐츠는 전문적 진단·치료를 제공하지 않고 모든 활동을 중단하거나 건너뛸 수 있다.

외부 모델·음원과 코드에는 각각 다른 이용조건이 적용될 수 있으므로 개별 파일의 라이선스를 확인한다. 공개 에셋에 고유한 로고나 사진이 포함되는지 점검하고 오픈소스 배포에 필요한 저작권·라이선스 고지를 유지한다.

최종 성과는 구현된 기능과 시연 기록, 사용자 평가를 근거로 보고한다. 실제 호흡 측정이나 장기적 정서 개선을 검증한 것으로 표현하지 않는다. 향후에는 모바일 조작, 접근성, 공간 선택 다양화 등을 검토하되 현재 학기에는 PC 기반 작은 정원의 완성도를 우선한다.

## 기존 PDF 편집 시 함께 고칠 사항

- 3쪽 목차가 본문의 실제 I~IV 구성과 다르고 페이지 번호가 #으로 남아 있어 실제 제목과 번호로 갱신한다.
