## 첫 프로젝트 생성 절차

아래는 **개발자가 최초 프로젝트를 만들 때 실행할 안내**입니다. 이번 작업에서는 실행용 앱, 패키지 설치, GitHub 저장소, 서버와 배포를 생성하지 않았습니다. 새 폴더 `mind-garden`을 사용합니다. 같은 이름의 폴더가 이미 있으면 내용을 확인한 후 재사용하고 명령을 반복하지 않습니다.

### 공통 루트와 클라이언트

작업 폴더의 PowerShell에서 실행합니다. 옵션 인자가 실행 프로그램에 전달되도록 아래 명령은 Windows의 `npm.cmd`를 사용합니다.

```powershell
New-Item -ItemType Directory -Path mind-garden
Set-Location mind-garden
npm.cmd init -y
npm.cmd pkg set private=true --json
npm.cmd pkg set type=module
New-Item -ItemType Directory -Path apps,shared,docs,asset-sources
npm.cmd create vite@latest apps/client -- --template vanilla-ts --no-interactive
New-Item -ItemType Directory -Path apps/server,apps/server/src
Push-Location apps/server
npm.cmd init -y
npm.cmd pkg set name=@mind-garden/server type=module
Pop-Location
npm.cmd pkg set 'workspaces[0]=apps/client' 'workspaces[1]=apps/server'
npm.cmd install --save-exact three socket.io-client --workspace apps/client
npm.cmd install --save-exact socket.io --workspace apps/server
npm.cmd install --save-dev --save-exact @types/three --workspace apps/client
npm.cmd install --save-dev --save-exact typescript tsx @types/node
```

Vite의 vanilla-ts를 사용합니다. 템플릿이 만든 버전과 설치 버전을 확인해 잠금 파일을 공유합니다. [Three.js 설치 안내](https://threejs.org/manual/pages/installation.html)

### 공통 설정과 실행 명령

`개발준비/공통설정/`의 세 파일을 `mind-garden/shared/`로 복사합니다. 이후 shared를 단일 원본으로 관리합니다. client/server에 별도의 응원 목록을 만들지 않습니다. 이번 폴더는 최초 설계 스냅샷으로 보관합니다.

루트 package.json에 아래 명령을 추가합니다. client의 `build`는 템플릿의 타입 검사와 Vite 빌드를 유지합니다.

```json
{
  "scripts": {
    "dev:client": "npm run dev --workspace apps/client",
    "dev:server": "npm run dev --workspace apps/server",
    "build:client": "npm run build --workspace apps/client",
    "check:server": "tsc --noEmit -p apps/server/tsconfig.json"
  }
}
```

server package.json에는 `"dev": "tsx watch src/index.ts"`를 추가합니다. 서버 담당자는 `src/index.ts`와 `tsconfig.json`을 작성합니다. tsconfig는 strict, ES2022, NodeNext module/moduleResolution, Node 타입을 사용합니다. shared JSON을 읽는 방식과 실행 시 파일 위치를 확인합니다. client에서 JSON import를 사용하면 tsconfig의 `resolveJsonModule`을 확인합니다.

두 터미널에서 `npm.cmd run dev:client`와 `npm.cmd run dev:server`를 각각 실행합니다. 서버 엔트리 파일을 작성하기 전에는 서버가 실행되지 않습니다. 첫 작업은 실제 서버 엔트리와 기본 장면을 작성해 아래 환경 확인표를 통과하는 것입니다.

공통 Node 버전을 `.node-version`에 기록하고 `node --version`, `npm --version`, `npm ls --depth=0 --workspaces` 결과를 남깁니다. 서버 타입 검사와 클라이언트 빌드 통과 후 패키지 버전을 확정합니다.

### 실행 환경 초안

클라이언트 `.env.example`:

```dotenv
VITE_SOCKET_URL=http://localhost:3001
```

서버 `.env.example`:

```dotenv
HOST=127.0.0.1
PORT=3001
ALLOWED_ORIGINS=http://localhost:5173,http://127.0.0.1:5173
```

서버 코드에서 환경변수를 실제로 읽도록 구현합니다. 포트는 client 5173, server 3001로 고정하고 충돌 시 문서·환경값을 함께 수정합니다. `VITE_` 값은 브라우저에 공개되므로 비밀번호·API 키를 넣지 않습니다.

같은 PC의 독립 탭 시험 뒤 다른 PC를 연결합니다. 다른 PC의 `localhost`는 그 PC 자신이므로 서버 PC의 LAN IP를 사용해야 합니다. LAN 시험 때 client `--host 0.0.0.0`와 서버 listen 주소를 조정하고 실제 client origin을 허용 목록에 추가합니다. 방화벽과 학교 네트워크의 연결 가능 여부를 확인합니다. 외부 접속은 실행 환경 선정 후 설정합니다.

## Git과 공유 규칙

- 현재 기존 기획자료와 미추적 파일을 유지합니다. 자동 커밋이나 원격 공개를 하지 않았습니다.
- 팀 공동 저장소 위치·공개 여부·세 명의 접근권한을 확인합니다.
- 기능 브랜치는 `codex/checkin`, `codex/forest`, `codex/realtime`처럼 구분합니다. 기존 팀 규칙이 있으면 따릅니다.
- 담당자가 기능을 올리면 작업표의 검토자가 코드와 실행을 확인합니다.
- 매주 전체 흐름을 통합하고 정상·중단 흐름을 함께 시연합니다.
- package-lock.json과 `.env.example`, 라이선스 고지는 공유합니다. node_modules, dist, 실제 `.env`, 임시 이미지, 평가 원응답은 코드 저장소에서 제외합니다.
- Blender 원본과 실행용 GLB를 구분합니다. 큰 에셋은 용량을 확인하고 필요한 파일 관리 방식을 결정합니다.

향후 앱의 `.gitignore` 예시:

```gitignore
node_modules/
dist/
.env
.env.*
!.env.example
*.log
tmp/
evaluation-private/
```
